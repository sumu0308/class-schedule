## 这个 App 能做什么

把「这周上什么课、在哪上、几点上」在一屏里看清楚，并且让你把自己学校的课表录进去。

- **一周课表网格**：左侧节次时间，右侧 5 天（可切 7 天）
- **周次概念完整**：开学日期决定"今天是第几周"，支持按周次范围 + 单双周显示课程
- **录课很快**：长按课表空白格即可新增，自动带上该格的星期与节次
- **提醒、导入**：见[路线图](#路线图)，尚未实现

## 装到手机上（普通用户）

1. 拿到 `app-release.apk`（构建产物见下文，或从 [Releases](../../releases) 下载）
2. 把 APK 传到手机。**推荐**：电脑与手机连同一个网络，在电脑上双击 `serve-apk.bat`，用手机浏览器打开它打印出的地址即可下载
3. 手机点安装，提示"未知来源应用"时允许一次
4. 首次打开后建议先进 **「学期」** 把**开学日期**改成你学校校历上第 1 周的周一

> 注意：当前 APK 使用**调试签名**（v2 签名有效，可正常安装）。正式发布签名在 M6 阶段接入。

## 自己构建（开发者）

### 你需要什么

| 依赖 | 要求 | 说明 |
| --- | --- | --- |
| JDK | 17 或更高 | 本机实测 JDK 21 可用 |
| Node.js | 18 或更高 | 只用于项目自带的工具脚本，不参与 App 运行 |
| Android SDK | **不需要自己装** | 项目自带安装脚本，装进项目目录 |
| Android Studio | **不需要** | 命令行即可打包；想改界面再另装 |

### 三步跑起来

```bat
:: 1. 安装 Android SDK 到项目内 .android-sdk（约 250 MB，支持断点续传）
node tools\install-sdk-packages.mjs

:: 2. 准备 Gradle 与 wrapper（约 145 MB）
node tools\setup-gradle-wrapper.mjs

:: 3. 打包
build.bat
```

产物在 `app\build\outputs\apk\release\app-release.apk`。

### 常用命令

| 命令 | 作用 |
| --- | --- |
| `build.bat` | 打正式包（release） |
| `build.bat debug` | 打调试包 |
| `build.bat test` | 只跑单元测试 |
| `build.bat clean` | 清理后重新打包 |
| `serve-apk.bat` | 在局域网内共享 APK，手机浏览器直接下载 |

也可以直接用 Gradle：`gradlew.bat assembleRelease`、`gradlew.bat testDebugUnitTest`。

### 环境变量

`build.bat` 已内置好，无需手动配置。若你要单独调用 Gradle：

```bat
set JAVA_HOME=D:\JDK\jdk21
set ANDROID_HOME=<项目目录>\.android-sdk
set GRADLE_USER_HOME=<项目目录>\.gradle-home
```

### 设计取舍（为什么这么做）

| 决定 | 原因 |
| --- | --- |
| `Course` 直接存"一条上课安排"（星期+节次+周次），而不是"课程实体 + 多个时间段"两级模型 | 教务导出与手工录入的粒度天然就是安排级，单机场景无需归一化，实现与校验成本都更低 |
| 周次用文本表达式（`1-8,10-16`）而非关联表 | 单学期数据量小，查询时在内存展开即可；换取写入与备份的简单 |
| 课表网格用 Canvas 自绘 | 行高按分钟成比例、块跨行、块内塞两行小字，自绘比嵌套 Compose 布局更可控 |
| 不用 `java.time`，只用 epochDay 整数运算 | `java.time` 在 minSdk 24 上需要 API 26 或额外脱糖配置；本项目只需要"天数差"和"星期几" |

## 踩过的坑（重要）

这些是在真实环境（Windows 11 + 校园网/手机热点，代理软件未启动）里踩到并已修复的问题。它们**不影响你使用 App，但影响你构建**，所以记录下来。

| 现象 | 根因 | 处理方式 |
| --- | --- | --- |
| 所有下载失败，`无法连接到远程服务器` | Windows 系统代理指向 `127.0.0.1:7897`，但代理软件没启动；Java/Gradle 会照读注册表里的代理设置 | `gradle.properties` 里显式清空 `systemProp.*.proxyHost`，强制直连 |
| `sdkmanager` 报 `Failed to download any source lists` | 该工具内部的超时/重试策略在移动网络下顶不住（同一时刻 Java 直连其实只要 650 ms） | 弃用 sdkmanager，改用 `tools/install-sdk-packages.mjs` 直接下载官方组件包并校验 SHA1 |
| `gradlew.bat` 执行出一堆乱码命令 | 批处理文件里写了 UTF-8 中文注释，cmd.exe 按字节解析会错位 | wrapper 脚本改为纯 ASCII，并在脚本里留了注释说明原因 |
| `NoClassDefFoundError: org/gradle/wrapper/IDownload` | Gradle 9.x 把 wrapper 拆成 `gradle-wrapper-main` 与 `gradle-wrapper-shared` 两个 jar，生成脚本只拷贝了前者 | 从 `gradle-wrapper-main-*.jar` 内层取出官方完整 `gradle-wrapper.jar`（48 KB） |
| `Failed to find target with hash string 'android-37.0-ext2'` | AGP 9.4.1 期望的平台目录名与实际发布的 `platforms/android-37.2` 命名体系不一致 | 锁定 `compileSdk 36` + 配套版本的 AndroidX（版本目录里写了注释说明） |
| `validateSigningRelease` 报 `AccessDeniedException` | 调试密钥库默认位于 `C:\Users\<用户>\.android\`，受限环境下不可写 | 密钥库移入项目 `.keystore/`，构建脚本用推导出的绝对路径引用，项目可整体迁移 |
| Gradle 报 `Couldn't open current thread, error = 5` | 文件监视器在受限环境下无法工作 | 无害警告，不影响构建结果 |
| `git push` 报 `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS` | git 默认用 Windows schannel 做 TLS，在受限环境下取不到客户端凭据（与账号密码无关，握手前就失败） | 本仓库配置 `git config http.sslBackend openssl`，改用自带的 OpenSSL |
| `git push` 报 `Failed to connect to github.com:443 after 21000 ms`，但同一条命令重试就好了 | **本机到 github.com:443 的连接不稳定**（实测约 1/3 概率超时，成功时只要 1～10 秒）；`api.github.com` 一直稳定 | 用 `push.bat` 推送，失败会自动重试；别把这种超时误判成账号或密码问题 |

## 提交到 GitHub

仓库：<https://github.com/sumu0308/class-schedule>（公开）

```bat
git add -A
git commit -m "说明这次改了什么"
push.bat
```

**为什么要用 `push.bat` 而不是直接 `git push`**：这台机器到 `github.com:443` 的连接不稳定（实测约 1/3 概率超时，成功时 1～10 秒），而系统里 git 自带的凭据助手也起不来（每个助手都要经 `sh.exe` 启动，而 `sh.exe` 在本机直接崩溃 `couldn't create signal pipe, Win32 error 5`）。`push.bat` 把令牌接进 URL 并绕开凭据助手，失败自动重试最多 8 次：

```
push.bat                     → 推送到 main
push.bat -m "改动说明"        → 先提交全部改动再推送
set FORCE=1 & push.bat       → force-with-lease（只在重写过历史后用）
```

> **从 PowerShell 调用时注意**：不要写成 `cmd /c "push.bat -m \"说明\""` —— 嵌套引号会被解析掉，提交信息会变成一个双引号字符（这件事真的发生过，三个提交的信息都成了 `"`）。请用参数数组，让 PowerShell 自己负责加引号：
>
> ```powershell
> & cmd.exe /c .\push.bat -m '一句话说明'
> ```

推送后核对远程内容和本地是否一致（逐文件比对，并检查有没有误传构建产物）：

```bat
node tools/verify-remote.mjs
```

核对脚本会输出五项：仓库概况、最新提交、文件统计与顶层结构、关键文件内容抽查、本地与远程的同步状态。三种容易被误判成"出问题了"的情况，这里先说明：

| 现象 | 真实含义 |
| --- | --- |
| 刚推送完就核对，某个文件报"与本地一致=false" | **多半是 GitHub 读取延迟**，不是真的不一致。脚本已内置带 cache-buster 的重试；若仍报，等十几秒重跑一次再判断 |
| 报 `API 限流（配额 60 …）` | 脚本没拿到 gh 令牌、退回了匿名访问。匿名只有 60 次/小时，而一轮核对要十几次，很容易撞上。确认 `gh auth status` 正常即可（有令牌时是 5000 次/小时） |
| 报 `✗ 提交不一致 —— 本地有未推送的提交` | 这是**真的**，说明本地有提交还没推。跑一次 `push.bat` 即可 |

内容只包括源码、文档与脚本；`.android-sdk/`（约 790 MB）、`.gradle-home/`（约 1.7 GB）、构建产物与 APK 都由 `.gitignore` 排除，克隆后按[自己构建](#自己构建开发者)一节重新生成即可。

**排查过程中走过的弯路（如实记录）**

推送一直失败，我先把它当成认证问题，绕了三圈：

| 尝试 | 结果 |
| --- | --- |
| `gh repo create --push` 报 `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS` | 改用 `http.sslBackend=openssl`，**这条是有效的**，此后 TLS 层不再报错 |
| 配 `credential.helper "!gh auth git-credential"`，仍要手输用户名 | 写 `.cmd`、再写 `.ps1` 版助手，助手单独测都能取到令牌，但 git 始终不用它们 |

顺带发现并修正：初始化时的 `git add -A` 把我写提交信息用的临时文件 `commit-msg.txt` 一起提交了，已从提交中移除。

### 推送链路加固 — 2026-10-11

**改动：修掉提交信息被吞、重试间隔失效、押核脚本限流三处问题**

核对脚本第一次跑就报 `README.md 与本地一致=false`，看着像推送漏了文件。查下来是**读取延迟**：GitHub 的 contents 接口在刚 push 完的一小段时间里可能返回旧内容。顺着这条线又查出三个真问题：

| 问题 | 症状 | 修法 |
| --- | --- | --- |
| 从 PowerShell 调 `push.bat -m "说明"` | 嵌套引号被解析掉，**三个提交的信息都变成了一个 `"` 字符** | `push.bat` 里写明正确调用方式；已用 `tools/fix-broken-messages.mjs` 按完整哈希把那三个提交的信息改回来（只换 message，tree 与 parent 不变） |
| `timeout /t 3 /nobreak >nul` | stdin 被重定向时 `timeout.exe` 直接报 `Input redirection is not supported` 退出，**3 秒等待退化成立刻重试**，8 次重试几百毫秒就打完了 | 改成 `< nul >nul` |
| 核对脚本走匿名 API | 匿名只有 60 次/小时，而一轮核对要十几次，跑几轮就 `HTTP 403 rate limit exceeded`，**与仓库内容对不对毫无关系** | 改用 `gh` 令牌（5000 次/小时），取不到才退回匿名并明确提示 |

另外两处顺带改好：

- 核对脚本读本地 git 状态时不再受沙箱限制。原以为是"沙箱禁子进程"，实际是**禁管道**——把子进程 stdout 接到临时文件句柄上就能读，于是"本地是否有未推送提交"这项恢复工作，不再降级跳过
- 补上 `uncaughtException` / `unhandledRejection` 处理：之前限流抛错时 Node 会以 libuv 断言崩溃（`UV_HANDLE_CLOSING`）退出，连结论都不打印

`tools/fix-broken-messages.mjs` 的一个设计取舍：**待修提交按完整哈希写死**，不按"信息内容"匹配。因为那几个提交的信息都只是一个 `"`，光看内容根本分不出谁是谁——按内容模糊匹配很容易改错对象。

### 0.4.0 — 2026-10-11

**改动：排版比例改用"节次时长"作基准，并支持按屏幕高度自适应**

起因是核对文档与代码是否一致时，怀疑排版比例算法有问题。追查过程中**两次判断都被数据推翻**，最终结论如下。完整数值可用 `node tools/verify-layout-math.mjs` 独立复算。

- 旧算法：`比例 = 表头高 × 2 ÷ 节次间隔的中位数`
  本作息 7 个间隔是 `20,20,20,170,20,20,20`，排序后**索引 3 的值是 20 分钟**（午休 170 排在最后），
  于是 `34 × 2 ÷ 20 = 3.40`，被夹到上限 `2.2` → **40 分钟的行高约 88 dp**。
- 新算法：`比例 = 80 dp ÷ 节次时长的中位数` = `80 ÷ 40` = **2.0**，再按屏幕可用高度放大，最后夹到 `[0.9, 2.2]`。
  → **40 分钟行高 80 dp**，整段 100 分钟 200 dp。

**需要如实说明**：新旧行高只差 8 dp（88 → 80），**视觉上几乎看不出区别**。这次改动的真实价值不是"修好了一个显示缺陷"，而是：

1. 旧写法依赖"休息时长"这个与行高无关的量，属于脆弱的间接推导；新写法直接用节次时长。
   例如把午休时长改掉，旧算法会连带改变**所有**行高，新算法不会。
2. 新增**按屏幕高度自适应**（`build(periods, availableHeightDp)`），大屏能铺满而不是固定密度。

**过程中的两次错误判断（记录在此以免重蹈）**

| 判断 | 为何错 |
| --- | --- |
| "中位数被午休 170 污染 → 系数被压到下限 0.75 → 行高只剩 30 dp" | 取中位数是 `sorted[size/2]`，7 个元素取索引 3，落在 20 上，午休排在最后。**从未被压到下限** |
| 据此认定存在"行被压扁"的显示缺陷 | 实测旧值 88 dp，本来就可读。是拿"文档描述"当"代码事实"导致的 |

教训：**先算、再下判断**。这次是靠把算法独立复算一遍才发现的。

**其他改动**

- 课程块字号新增 `≥150 dp → 14 sp` 一档。
- 课表区域先量出可用高度再排版（`BoxWithConstraints` 的 `maxHeight`）。
- **左侧栏（节次号 + 时间刻度）宽度改为自适应**：8 小节作息下整天约 1220 dp，必然纵向滚动，此时把左侧栏由 70 dp 收窄到 48 dp（时间刻度字号同步降到 8 sp），宽度让给课表；若节次少到一屏放得下，则保留 70 dp。
- 新增防回归测试：比例系数不得落到下限、40 分钟行高必须落在 60–110 dp、改掉午休时长后比例系数必须不变、可用高度变大时行高不得缩小。

**测试**

- 共 **50 个单元测试全部通过**：`gradlew.bat testDebugUnitTest`

**已知问题**

- 需要你在真机上核对 40 分钟小节的**具体时间点**。目前是按"第 1 小节 08:00–08:40 + 休息 + 第 2 小节 09:00–09:40 = 第 1 大节 09:40 结束"推定的，若与校历不符，可在「学期 → 节次时间」里直接改。
- "拖动调课""课程搜索"等体验项尚未开始。

### 0.3.0 — 2026-10-11

**作息结构细化为 8 小节**

- 默认节次由 4 条（整段 100 分钟）改为 **8 条 40 分钟小节**：一天 4 个大节、每个大节 2 个小节，小节之间休息 20 分钟。
- 课表网格随之变为 8 行；课程块**字号改为随块高自适应**（字号 13→9 sp 分档，块矮时不再溢出）。
- 课程编辑新增**「第 N 大节」快捷选择**按钮，同时保留逐小节微调；下方提示会写明"共占 N 小节（第 X 大节）"或"跨第 X–Y 大节"。
- 升级迁移同时识别两代旧模板：0.1.0 的 12 小节（首节 08:00-08:45）与 0.2.0 的 4 节（首节 08:00-09:40）。

**一个被测试纠正的设计错误**

最初把"大节"实现为*按时间间隔自动识别*（间隔超过 30 分钟视为跨大节）。单元测试直接否掉了这个方案：实测数据显示 **9:40→10:00 的间隔也是 20 分钟**，与其它小节休息完全相同——

```
第 1 节结束 08:40 → 第 2 节开始 09:00   间隔 20 分钟
第 2 节结束 09:40 → 第 3 节开始 10:00   间隔 20 分钟   ← 这是跨大节边界，但间隔并无不同
第 3 节结束 10:40 → 第 4 节开始 11:00   间隔 20 分钟
第 4 节结束 11:40 → 第 5 节开始 14:30   间隔 170 分钟  ← 午休，只区分上下午
```

改成**按结构两两配对**（`groupIntoBlocks(periods, periodsPerBlock = 2)`），并把这份实测间隔数据写成测试固化下来：若作息将来改成跨大节有明显长间隔，测试会失败并提醒重新评估策略。

**测试**

- 新增 10 个 `PeriodBlockTest` 用例（大节分组、可配置每节小节数、乱序输入、空输入、实测间隔数据固化）。
- 共 **45 个单元测试全部通过**：`gradlew.bat testDebugUnitTest`

**已知问题**

- 需要你在真机上核对 40 分钟小节的**具体时间点**。目前是按"第 1 小节 08:00–08:40 + 休息 + 第 2 小节 09:00–09:40 = 第 1 大节 09:40 结束"推定的，若与校历不符，可在「学期 → 节次时间」里直接改。
- （早前此处曾记一条"课表行偏挤、行高只有约 30 dp"，**该记录是错的**：0.3.0 的实际行高是 88 dp，本来就可读。误判原因与更正见 0.4.0 一节的"两次错误判断"表。）
- "拖动调课""课程搜索"等体验项尚未开始。

### 0.2.0 — 2026-10-11

- **开学日期改用系统日历选择**，精确到年月日；非周一时给出提示与"改为周一"一键修正。此前只有"提前/推后一周"的 7 天粒度，无法对准校历。
